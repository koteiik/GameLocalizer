# Runtime Translation Dictionary v1 (local development)

GameLocalizer pretranslates imported Runtime UI entries through the existing offline TranslationService and Translation Memory. The game-side module has no dependencies on GameLocalizer, ModelHost, ONNX, HTTP clients, sockets, or translation services. It loads one ready JSON dictionary at startup and only performs exact in-memory lookup and UI replacement while the game runs. Unknown strings retain their original text and continue into the read-only collector. The game works without GameLocalizer running.

Runtime UI now has an editable Russian column plus Status and RuntimeDictionary. Manual edits apply to all contexts of the same exact original text and persist in runtime-translations.json and Translation Memory. Import restores persisted translations and validated memory candidates. Existing manual overrides take priority over memory, imported values, and offline output. Conflicting highest-priority values are marked DictionaryConflict and omitted from the dictionary. Empty, unchanged, non-Russian, and invalid placeholder/markup translations are omitted. The current offline model is EN→RU; unsupported languages and poor model output may need manual correction.

Buttons: Перевести новые (only untranslated originals, deduplicated across contexts); Обновить Runtime словарь (explicit save and owned installation); Открыть Runtime словарь. Successful pretranslation offers a visible Да/Нет prompt before updating the dictionary. There is no silent deployment after pretranslation. The existing Runtime UI export and raw-capture folder buttons remain available.

Master files:
%LOCALAPPDATA%/GameLocalizer/RuntimeDictionary/<canonical-path GameId>/runtime-dictionary.json
%LOCALAPPDATA%/GameLocalizer/RuntimeDictionary/<canonical-path GameId>/runtime-translations.json

The ready copy is installed beside the collector as BepInEx/plugins/GameLocalizerCollector/runtime-dictionary.json. SchemaVersion=1, GameId, GeneratedAt, Version, EntryCount, and Entries are included. Saves use a same-directory temporary file, fsync, then atomic replacement. The dictionary copy and staging path are ownership-tracked by SHA256. Upgrades preserve dictionary ownership; collector uninstall removes the owned copy while preserving master data and Translation Memory. Ordinary Apply/cleanup does not manage the dictionary. Close the game before installation, removal, or dictionary copy updates. Restart the game after updating the dictionary; no hot reload.

Runtime module: prefix interception for Unity Text/text and plain TMP setters; formatted TMP values are inspected after GenerateTextMesh, then re-parsed and regenerated with the ready Russian value in that callback. A recursion guard prevents loops, and the collector records the original rather than the module's own replacement. Rendered-only TMP matches with rich markup not present in the captured value are skipped to preserve formatting. This limits v1 coverage for such cases. Exceptions in the module are isolated; an absent, malformed, wrong-game, oversized, or unsupported-schema dictionary disables translation while collection continues.

Dynamic patterns are separately restricted to one explicitly authored {{A}}...{{Z}} token with at least three literal prefix characters. There are no generated regular expressions or guessed templates. A pattern does not synthesize a dictionary entry from dynamic captures; it must already exist as an authored template. Replacement captures are bounded to 128 characters, reject control characters and markup/brackets, and ambiguous matching patterns fail closed. Exact lookup remains ordinal and performs no normalization. At most 128 dynamic patterns are indexed by initial character; exact dictionary lookup has constant expected cost and no per-lookup allocation.

Synthetic tests cover dictionary schema, generation, conflicts, manual priority, cross-context Translation Memory reuse, atomic writes, Unicode, corrupt/missing files, load once, Unity/TMP replacement, unknown collection, explicit placeholders, preservation of original captures, uninstall, forbidden dependencies, and 10,000-entry / 100,000-lookup allocation checks. They use Unity/BepInEx/Harmony stubs and do not prove real Harmony detours, font glyph availability, interactions with other translation mods, or gameplay FPS. Real AI-Shoujo validation remains manual. No gameplay is started automatically.

Primary API references: [Harmony patching](https://harmony.pardeike.net/v2/articles/basics.html), [TMP_Text](https://docs.unity3d.com/ja/Packages/com.unity.textmeshpro%403.0/api/TMPro.TMP_Text.html).
