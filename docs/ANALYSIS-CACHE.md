# Persistent game analysis

The installed application stores analysis in `%LOCALAPPDATA%\GameLocalizer\analysis.db`, separate from `memory.db`, models, jobs, settings and game backups. SQLite WAL transactions publish a complete replacement session by updating the game's active snapshot pointer only after extraction, identity reconciliation and memory restoration succeed. The active and previous committed sessions are retained; older committed sessions are retired. Normal application shutdown preserves this database.

Game identity is a SHA256 of the normalized absolute game root. Snapshots retain engine/confidence, analysis time, per-file physical and relative paths, size, UTC write ticks, SHA256, adapter and localization slot. Rows retain original/translation, classification/confidence, selection/status, stable identity, manual flag, applied flag and translation source. Stable row identity uses the game root identity, relative file, adapter, displayed key and occurrence, rather than a physical line number. Duplicate occurrences remain separate.

Selecting a game loads its snapshot and one page of rows automatically, with counts/date and usable Translate/Apply commands. Validation checks existence, length and timestamp first; SHA256 is read only when metadata differs. Known source directory timestamps detect additions/deletions without a complete directory walk on opening. Additions in previously untracked branches are discovered by the explicit incremental refresh, which enumerates the supported resource catalog but only decodes new/changed files. Unchanged files copy their disk-backed rows rather than being classified again. Cached unsupported Unity candidates also reload. Failed text parses retain a diagnostic and a fingerprint, so an unchanged invalid file does not force repeated parsing.

«Найти текст» becomes «Обновить анализ» when a snapshot exists. Its right-click menu also offers «Полный перескан» and «Забыть анализ игры». Forget requires confirmation and removes only that game's analysis rows/snapshot/discovery results. It does not modify translation memory, models, backups or settings.

Changed-file reconciliation preserves manual edits and known translations when Original still matches. Known applied Russian matches restore the snapshot's English Original, classification and confidence. If no snapshot exists, a hash-verified owned backup/manifest supplies the original records. A genuinely changed source retains the previous translation as an unselected `SourceChanged` suggestion; it cannot pass Apply automatically. Translation Memory remains available for exact source matches. Translation jobs skip already known rows.

Apply refreshes the affected fingerprints and applied flags. Restore/Cleanup retain rows and translations while refreshing the restored file metadata and clearing applied state. Original values remain available for another Apply.

Analysis schema version 1 migrates missing metadata columns in place. An unreadable SQLite database or unsupported schema is moved to `analysis.db.unreadable-<timestamp>` with its WAL sidecars before a fresh cache is created; the retained file can be recovered. No translation-memory database is moved or deleted.

Regression coverage includes restart/automatic UI restore, model/manual translations, selection/classification/path/slot, fast unchanged validation, changed/new/deleted files, duplicate keys after line insertion, full rescan, applied originals with snapshot or backup, source-change suggestions, Restore/Cleanup retention, scoped forget, schema migration, unreadable-cache recovery, invalid-file reuse and cancelled publication. A read-only installed-library CLI supports `--cache` verification against AI Shoujo; it updates only analysis/user-data state and does not translate or modify the game.
